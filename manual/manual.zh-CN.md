## 1. 这是什么

TIFA 强制对齐器可以直接读文本，但它需要一个载体来回答三个问题：**哪里该断词、哪一段是什么语言、
哪个字读什么**。这个载体就是 PFML（Pronunciation Flow Markup Language）。

手写 PFML 既难又容易出错，而代价不小：**对齐器遇到不合法的 PFML 会直接跳过整个样本，没有回退**。
MinLabel 时代那套"音频配 `.lab`"的流程在文本优先的新链路里已经没有位置。MaxLabel 填的就是这个空。

```
AudioSlicer ──► (文本 / .lab+json / .pfml)
                        │
                        ├──► MaxLabel ──► song.pfml          ← 本项目
                        │
                        └──► TIFA ──► TextGrid + diagnosis.json
```

**输入**（都非必需）：音频 + `.pfml` / `.txt` / `.lab` / `.json`
**输出**：只有 `.pfml`

### 文本优先，音频可选

这是 MaxLabel 和 MinLabel 最大的区别。MinLabel 是**音频配标签**，MaxLabel 是**文本配标注**。

因此**没有 wav 也能正常工作**：打开一个只有 `.txt` 的目录，段落照常列出、语言照常切分、
`.pfml` 照常写出。音频面板只是不出现，而不是整个工具降级。工作顺序也随之改变——
过去是"先听再标"，现在是"先把文本和发音定下来，音频只在需要时才看"。

### 不做什么

- **不做对齐**。这是 TIFA 的事，不是本工具的事。
- **不做切片修正**。切错了是上游的问题。
- **不做 TIFA 输出侧的转换**。TextGrid / `diagnosis.json` 的后续处理不在范围内。

## 2. 安装

### 发行版压缩包（推荐）

从 [Releases](https://github.com/KakaruHayate/MaxLabel/releases) 下载对应平台的压缩包，
解压后直接运行，**不需要单独安装 Qt**：

| 平台 | 文件 | 运行 |
|---|---|---|
| Windows x64 | `MaxLabel-windows-x64.zip` | `MaxLabel.exe` |
| Linux x64 | `MaxLabel-linux-x64.tar.gz` | `./MaxLabel` |
| macOS arm64 | `MaxLabel-macos-arm64.tar.gz` | `MaxLabel.app` |

压缩包里已经包含语言检测模型（`models/lid.176.bin`），解压即可用。

> **命令行程序 `maxlabel_cli` 在同一个目录里，它不依赖 Qt。** 只做批量校验或脚本处理时用它，
> 不需要图形环境。

### 从源码构建

需要 CMake ≥ 3.18、支持 C++17 的编译器，以及 Qt 6（Widgets / Multimedia / Svg / LinguistTools）。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

只想要核心库和命令行、机器上没有 Qt：

```bash
cmake -S . -B build -DMAXLABEL_BUILD_UI=OFF
```

`MAXLABEL_BUILD_UI` 默认为 `ON`——此时缺 Qt 是**报错**而不是静默降级，
以免出现"CI 通过了但从未编译过界面"这种情况。

## 3. 快速开始

```bash
MaxLabel /path/to/dataset
```

1. 左边列出了目录里找到的**段落**。点一条打开。
2. 中间的**文本**是整行歌词。下面的**字符条**把它铺成一个个方块。
3. **点方块**选中一个字，**按住拖过几个方块**选中一段，**双击**直接指定发音。
4. 选中之后按 `1`–`5` 指定语言，`W` 标记为词，`P` 指定发音，`I` 插入音素。
5. 底部的 **PFML 框**显示实际会写出去的内容。`Ctrl+S` 保存（其实每次改动都已经自动写盘了）。

按 `F1` 打开内置手册，那里有同样的快捷键表。

## 4. 概念：段落、文本来源、输出

### 段落（segment）

**共享同一个文件名的文件构成一个段落**：

```
song.wav      ← 音频（可选）
song.pfml     ← PFML（可选）
song.txt      ← 纯文本歌词（可选）
song.lab      ← MinLabel 时代的音节行（可选）
song.json     ← MinLabel 时代的工程边车（可选）
```

这四个文本文件里，**只有一个**会成为这个段落的文本来源，优先级为：

```
.pfml  >  .txt  >  .lab
```

和对齐器一致。`.json` 不提供文本，它提供音节/音素序列，在与 `.lab` 配对时用于预填。

**打开 `.pfml` 时读的是标记本身，不是把标记当正文显示。** 工具会把 `<scope>` 解析成语言区间、
`<word>` 解析成词边界、带 `phonemes` 的 `<word>` 和 `<phoneme>` 解析成发音标注，
所以编辑本工具自己写出的文件不会把它弄坏。

### 输出

**只有 `.pfml`，写在段落自己所在的目录里，文件名是 `<id>.pfml`。**

每次修改都**立即落盘**，不存在"待保存"状态——切换段落、切换目录都不会丢东西。

### 一个 PFML 本身的限制

`<word>` 只能嵌在 `<scope>` 里，不能反过来。所以**跨语言边界的词无法表达**：
若一个词的一半是中文、一半是日文，工具会在状态栏报告并把它留作普通文本，
而不是悄悄拆开或丢掉。

## 5. 界面

```
┌────────────┬──────────────────────────────────────────────┐
│ 段落       │ 音频（没有音频时整块收起）                    │
│            ├──────────────────────────────────────────────┤
│ 项目       │ 走带 │ 标注动作 │ 语言快捷 │          计时     │
│            ├──────────────────────────────────────────────┤
│ 选区语言   │ 字符条                                        │
│            ├──────────────────────────────────────────────┤
│ 词边界     │ 文本                                          │
│            ├──────────────────────────────────────────────┤
│ 发音       │ PFML（可编辑）                                │
└────────────┴──────────────────────────────────────────────┘
```

版式参考 Aegisub：**音频在上、工具条夹在中间、文本在下**。频谱是时频图——时间沿 X、频率沿 Y——
所以音频区做成通栏而不是侧边窄条，窄条里读不出频谱。

### 左侧栏

| 分组 | 内容 |
|---|---|
| 段落 | 目录里找到的所有段落。未保存的带 `*`，没有音频的标「（无音频）」 |
| 项目 | 打开文件夹 / 保存 / 上一条 / 下一条 / 撤销 / 重做 |
| 选区语言 | `1 中文`、`2 日语`、`3 英语`、`4 韩语`、`5 粤语`，每个按钮上带着**该语言在文本里的颜色** |
| 词边界 | 标记为词 / 清除词边界 / 重新切分语言 |
| 发音 | 指定发音 / 插入音素 / 非词汇音 / 清除覆盖 |

## 6. 操作

### 字符条：主要的操作方式

整行被铺成一个个方块，**一个字符一块，拉丁文按词**。这是为了绕开一个具体的困难：
中日文没有词边界可以吸附，在文本框里拖选要精确到字，选完还要跑去侧栏找按钮——
这一路既慢又容易标错。

| 手势 | 结果 |
|---|---|
| **单击** | 选中该方块 |
| **拖拽** | 选中两块之间的这一段（一个词通常不止一个字，`<word>` 要的就是这个范围） |
| **双击** | 打开该方块的指定发音弹窗；对 `+` 标记则是修改/删除该插入音素 |

方块本身带着状态，不需要去别处查：

- **方块下方的字**＝指定给它的读音（`的` 上方显示 `di`，字在读音下面）
- **底部青色横杠**＝这个词已固定
- **点线边框**＝读音是手写的；音素不在词表里时转为**红色**
- **`+n` 方块**＝在这里插入了一个 `n`；它没有宽度，所以单独占一块

### 标记的覆盖规则

**后加的标记在它标明的范围内覆盖先前的标记。** 具体分两种：

- **词边界**是纯标记，重叠时**保留没被压到的部分**。在已有的 `今天天气` 里标 `天气`，
  `今天` 会作为独立的词留下来，而不是被整块吃掉。
- **发音**带值，重叠时**整体替换**，不做切分。为一个区间写的读音不是短区间的读音，
  切一半下来是**错的值**而不是折中的值。

### 反选

**同一段上重复同一个操作就是取消它**：

| 操作 | 反选 |
|---|---|
| `W` 标记为词 | 再按一次 `W`（当它已经正好是这个词时） |
| `P` 指定发音 | 弹窗里的「删除」 |
| `I` 插入音素 | 双击 `+` 标记，弹窗里的「删除」；或在同一位置重新插入（替换，不会叠成两个） |
| 语言 | 用「重新切分语言」（`R`）丢弃自动推导的部分 |

### 撤销

**整个窗口一条历史**，覆盖文本、语言、词、发音、PFML 编辑。

文本编辑在停止输入后合并成一步（打字不会每个字符留一条），所以 `Ctrl+Z` 撤销的是"一次改动"
而不是"一个按键"。文本框和 PFML 框都没有自己的撤销栈——一个自带撤销栈的文本控件会悄悄忽略
所有标注操作，那比没有撤销更糟。

### 修改过语言之后

手动标过语言的段落，**改动文本会重新推导语言区间**（旧偏移已经不对应新文本了）。
状态栏在手动标记存在时会提示这一点，不是静默丢弃。想保留手动结果就不再动文本，
或者用 `R` 明确地重新切分。

## 7. 音频

音频**不是必需的**。没有音频时音频区、走带和计时一起收起，标注动作那一半工具条仍然留着——
标注是文本操作，和有没有录音无关。

| 操作 | 说明 |
|---|---|
| 点击波形 | 移动播放光标 |
| 拖拽波形 | 划定选区 |
| `≋` | 波形 / 频谱切换 |
| `▶` | 播放选区；没有选区就播放整段 |

**频谱**是时频图：时间沿 X、频率沿 Y、对数频率轴（60 Hz–10 kHz）。动态范围以峰值为基准向下
75 dB，经过 gamma 校正，所以人声的谐波结构和共振峰在真实演唱上也能看清。

`▶` 旁边的 `«` `»` 前后微调 0.5 秒，`⌫` 清除选区。

## 8. PFML 框

底部的框就是**实际会写出去的内容**，而且**可以直接编辑**。

输入的内容会被读回上面的文本和字符条——两边不会各说各话。

**解析不了的片段什么都改不了：**

- 框变红
- 由它推导出的面板（文本、字符条）**变暗**，而不是继续显示上一次的解析结果
  （后者读起来像"没问题"）
- 原因写在状态栏和框的工具提示里

撤销走的是整个窗口那一条历史，所以 `Ctrl+Z` 撤的是"这次编辑"而不是逐个按键。
输入停一下（1 秒）才会应用，避免每敲一个字符就报一次语法错。

## 9. 语言切分规则

语言切分借的是 GPT-SoVITS 前端那一套（`split-lang` 预切 + BudouX 分词 + fastText 检测），
因为它在多语言歌词上的表现是验证过的。

**核心原则：能用字形定下来的就绝不猜。**

| 文字 | 判定 |
|---|---|
| 假名（平/片假名） | 日文 |
| 谚文（한글） | 韩文 |
| 拉丁字母 | 英文 |
| **汉字** | **不猜** |

汉字被中文、日文、粤语共用，看一眼是分不出来的。所以一段汉字在没有更多信息时会被报成
**未定**——在文本里显示为**红色波浪线而不是颜色**，因为颜色读起来像"已经有答案了"，
而这里还没有。你可以按 `1`/`2`/`3` 明确指定。

数字串、标点、空白单独成段时会就近归并，不会被当成某种语言。

## 10. 词表与 G2P

两者都是**可选的**，不配也能用——手打音素即可。配上之后多两件事：

- **词表**（`--vocab <文件>`，每行一个音素）：**逐个音素校验**，不在表里的会被点出来，
  而不是等到对齐时才发现整个样本被跳过。
- **G2P**（`--g2p-dir <模型目录>` 或 `--g2p <config.json>`）：指定发音的弹窗里会
  **列出词典的候选**，点一下即填。这对中日文的多音字尤其有用。

G2P 用的是 [tifa.cpp](https://github.com/KakaruHayate/tifa.cpp) 的 `tifa_ggml_g2p`
——和 TIFA 自己用的是同一份代码，所以"工具里能查到的读音"和"对齐器会查到的读音"一致。

## 11. 命令行

`maxlabel_cli` 不依赖 Qt，适合批量处理和脚本。

```
maxlabel_cli — PFML project tool

  scan <dir>                 列出目录里的段落
  show <dir> <id>            打印一个段落的 PFML
  validate <file.pfml>       语法检查一个 PFML 片段
  set <dir> <id> [file]      写入 <id>.pfml（不给文件则读 stdin）
  langs <file> [-l <lang>]   按语言切分文本，打印 PFML
  phoneme <symbol> [-l zh,en] [--vocab <file>]
                             用词表检查一个音素
  candidates <text> --g2p <config.json> [--dicts <dir>] [-l zh,en]
                             列出 G2P 给出的候选读音
```

全局选项 `--models <目录>` 指定数据文件（BudouX 模型、检测器权重）的位置。

`validate` 在脚本里最有用——它和 GUI 保存前走的是**同一个校验闸门**：

```bash
for f in out/*.pfml; do maxlabel_cli validate "$f" || echo "BAD: $f"; done
```

## 12. 快捷键

### 全局

| 键 | 动作 |
|---|---|
| `Ctrl+O` | 打开文件夹 |
| `Ctrl+S` | 保存（实际每次改动都已写盘） |
| `Z` / `X` | 上一条 / 下一条 |
| `Ctrl+Z` | 撤销 |
| `Ctrl+Shift+Z` / `Ctrl+Y` | 重做 |
| `F1` | 手册 |

### 标注

| 键 | 动作 |
|---|---|
| `1` `2` `3` `4` `5` | 选区语言：中文 / 日语 / 英语 / 韩语 / 粤语 |
| `W` | 标记为词（再按一次取消） |
| `P` | 指定发音 |
| `I` | 插入音素 |
| `R` | 重新切分语言 |

### 音频

**这些键只在音频区获得焦点后才生效**，所以 `Space` 在文本框里仍然是空格。

| 键 | 动作 |
|---|---|
| `Space` / `B` | 播放选区，或整段 |
| `H` | 停止 |
| `Q` / `W` | 后退 / 前进 0.5 秒 |
| `←` / `→` | 同上 |
| `Ctrl+Space` | 从**任何位置**播放 |

## 13. 已知限制

- **跨语言边界的词无法表达**（见 §4）。工具会报告，不会静默处理。
- **`<reading>` / `<path>` / `<group>` 三层结构不建模。** 这类片段在文本面板里打开会被拒绝，
  并说明原因，而不是"半懂"地读进来再写坏。
- **手动指定语言之后，改动文本会重新推导语言区间**（见 §6）。旧偏移不再对应新文本。
- **窗口很窄时**，工具条右侧的语言按钮可能被裁掉。侧栏里都有同样的功能，也都带数字快捷键，
  所以是可看性而不是功能问题。
- **不打包 Qt 自带的翻译**，所以少数 Qt 内部字符串（主要是 Linux 上的文件对话框）是英文。
  应用自身的界面文字、以及对话框上的标准按钮（确定/取消/关闭）都是翻译好的。
